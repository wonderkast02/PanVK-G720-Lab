# Contributing

The Lab records evidence; the main repository fixes driver code.

A technical claim should include date, device/GPU, Kbase/CSF identity,
source commit, runtime versions, expected/observed behavior, reproduction,
first real failure, relevant logs/artifact hashes, limitations and evidence
status.

Use the status vocabulary in `docs/EVIDENCE_MODEL.md`. Failed hypotheses are
valuable historical evidence and should be marked rather than silently erased.

Do not submit tokens, passwords, private keys, personal data, proprietary APKs
or duplicate Mesa source trees. Runtime-specific workarounds must not be
presented as core PanVK fixes without causal proof.
